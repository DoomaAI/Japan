A private iPhone Home Screen web app, prepared for a new GitHub repository and Vercel project with Neon Postgres and private Vercel Blob storage. No App Store review is needed.

## Setup in GitHub and Vercel

1. Create a **private** GitHub repository, e.g. `japan-family-companion`. Upload this folder's contents to the repository root. It contains your family guide; do not make the repository public.
2. Import the repository into Vercel as a new project. Framework: Vite. Build command: `npm run build`. Output: `dist`. Use Node.js 22 or newer. The included Vercel functions serve all private data; do not deploy only the `dist` directory as a standalone static site.
3. Connect a new Neon database to the project and configure `DATABASE_URL` as a server environment variable. Use the Neon connection string, including its SSL settings. Never prefix it with `VITE_`.
4. Create a **private** Vercel Blob store and connect it. Configure `BLOB_READ_WRITE_TOKEN` server-side (or the Blob SDK's supported connected-store configuration). Do not use a public store for tickets.
5. Set `APP_ORIGIN` to the exact production HTTPS origin, with no trailing slash. Preview deployments should use isolated resources and their own exact origin.
6. Redeploy after setting environment variables.
7. On a trusted development machine, place the production `DATABASE_URL` and `APP_ORIGIN` in the ignored `.env.local` file and run `npm run create-owner` (Node 22+). This creates the database schema and initial itinerary, then writes the private parent link to `.private/owner-link.txt`. It does not print the link, expose a public setup endpoint or overwrite an existing owner. No setup key is used. Deliver the link privately and keep a recovery copy.
8. Open the private parent link, then the avatar → **Our family** → create a link for each family member. Send links yourself. Damien/Lauren links can edit and upload; Nate/Boston links can view and complete assigned activities. Each person opens their link in Safari before adding the app to the Home Screen.

### Getting a new version onto a phone

The service worker takes over as soon as a new build installs (`skipWaiting`), and the app checks for one each time it is brought to the foreground. When a newer build is ready the app shows a **Reload** prompt rather than waiting to be noticed. Without this a Home Screen app can sit on an old build for days, because a waiting service worker only activates once every copy of the app is closed.

### Home Screen icon

The shortcut icon is the guide's own cover — the title block, with Mount Fuji, the pagoda and the cherry blossom, cropped square from `public/cover.jpg` (which is guide page 1). It reads clearly at 60pt on an iPhone Home Screen.

| File | Used for |
| --- | --- |
| `icon-180.png` | `apple-touch-icon` — the iPhone Home Screen shortcut |
| `icon-192.png`, `icon-512.jpg` | Manifest icons, `purpose: any` |
| `icon-maskable-512.jpg` | Manifest `purpose: maskable` — the art is inset so Android's circular crop keeps the whole title |
| `favicon-32.png` | Browser tab |

`any` and `maskable` are deliberately separate files: a maskable icon used as `any` looks needlessly padded, and an `any` icon used as maskable has its edges cropped. The 512s are JPEG because the artwork is photographic — PNG made them roughly nine times larger for no visible gain — and they are left out of the offline shell, since they are only read when installing the app, which always happens online.

**iOS caches the Home Screen icon.** Anyone who already added the app to their Home Screen keeps the old icon until they remove the shortcut and add it again from Safari.

### Environment

| Variable | Purpose |
| --- | --- |
| `DATABASE_URL` | Neon Postgres connection; server only |
| `BLOB_READ_WRITE_TOKEN` | Private Vercel Blob access; server only |
| `APP_ORIGIN` | Exact production HTTPS origin; no trailing slash |
| `ANTHROPIC_API_KEY` | Optional. Switches on the features that call the Claude API — reading a menu from a photo, reading a document into English, judging the photo of the day, translating a phrase of our own, looking a planning-board idea up on the web, suggesting ideas for a place, asking what is near here, and reading the sumo card and its wrestlers; server only, never prefixed `VITE_` |
| `EMAIL_INBOX_SECRET` | Optional. The secret your mail provider puts in the inbound webhook URL. Without it `/api/email-in` answers 404 to everything; server only |

Looking a place up and suggesting ideas both run web searches on Anthropic's side, so they take longer than the other calls. `vercel.json` gives the API function a 60-second `maxDuration` for that reason; on a plan whose ceiling is lower, those two are the features that will time out, and everything else is unaffected.

### Forwarding email into the trip

Vercel cannot receive mail, so a provider accepts the message and posts it to the app. Postmark
is the one this is written against, because it hands out an inbound address without needing a
domain of your own.

1. Create a Postmark server and open its **Inbound** stream. It gives you an address like
   `abc123@inbound.postmarkapp.com`.
2. Pick a long random secret and set `EMAIL_INBOX_SECRET` in the Vercel project. Set the inbound
   webhook URL to `https://YOUR-ORIGIN/api/email-in/THE-SECRET`. A URL with basic-auth
   credentials works too: the app accepts the secret as the password.
3. Set `EMAIL_INBOX_SENDERS` to the addresses you will forward from, comma-separated.
4. Set `ANTHROPIC_API_KEY` if it is not already set. Without it the email is still stored; it is
   simply not read into English.
5. In Gmail, add a filter that forwards the confirmations you care about to the Postmark address.
   Forwarding by hand works just as well.

Redeploy after setting the variables. Until both `EMAIL_INBOX_SECRET` and `EMAIL_INBOX_SENDERS`
are set, `/api/email-in` answers 404 to everything, including a correct secret.

**What gets through.** A request without the secret is answered 404, the same as a wrong path, so
a caller guessing at the URL learns nothing. A message from an address that is not on the list,
one Postmark has marked as spam, or one with neither text nor attachments is answered 200 and
dropped — 200 rather than an error, so a mail provider does not retry it for hours. Be aware that
the sender list is a filter, not proof of identity: a `From` header can be forged by anyone who
learns the address. The address is therefore never published, the secret in the URL is the real
lock, and no forwarded email ever reaches the itinerary without a parent filing it.

**Where it can be filed.** Tickets & reservations is the default, attached to the whole trip, a
day or one activity. The other four put it where the family would have put it themselves: a new
activity on a chosen day, which behaves exactly like an activity typed in by hand and is locked
when given a time; the Options list, for something with no day yet; the planning board, so
everyone can vote on it before it gets a day; and the to-do list, for something to do or buy.
Files that came with the email are always kept in Tickets and attached to whatever was created,
so a voucher is never separated from the thing it belongs to. Where the email had no attachment,
only a ticket creates a document — everywhere else the English is already on the activity, idea
or job itself.

**Limits worth knowing.** Vercel stops a request body at about 4.5 MB, which is the real ceiling
on an attachment arriving by email — a larger one is rejected by the platform before the app sees
it. Up to ten attachments are kept per email, each subject to the same type and size rules as any
ticket upload, and a file that cannot be kept is still named on the email so you know it existed.
Forty emails can wait in the inbox at once; the oldest fall off after that. The English reading
runs when a parent opens the inbox, not when the email lands, because a mail provider allows a
webhook seconds and a careful translation takes longer than that — so an email nobody has opened
is still in its original language, and one that is opened with no Anthropic key set stays that way.

No Google API key is required for the embedded My Map or outbound directions. Google Places/Routes integration and Timeline import are **not implemented in this first build**. App buttons currently use official website/download pages, not undocumented native deep links. Automatic push reminders are also not implemented; Calendar and a user-installed Shortcut are the available reminder methods.

## Family link design

Invites contain 256-bit random tokens in the URL fragment, not query parameters. The browser exchanges the token for a Secure, HttpOnly, SameSite=Strict session cookie and removes the fragment before loading trip data. Neon stores token hashes, not raw invite/session tokens. Role and family identity are checked on the server. Invites/sessions expire after 45 days. Parents can revoke non-owner invites, invalidating their online sessions. The owner recovery link is deliberately protected from in-app revocation; keep it secure.

Offline copies cannot be remotely revoked. **Sign out and clear this phone** removes the local itinerary, progress queue and private downloads on that phone. Only download tickets on family-controlled devices. The API fails closed when production credentials are missing; the local preview mode is explicitly disabled on Vercel and in production.

## Offline behaviour

**What a phone can do with no signal at all.** Anything that records what happened, or adds something new, is saved on the phone and handed over when there is signal — it is still right whenever it lands. That covers ticking off activities and missions, skipping a mission, Eye Spy, ride checklists, food ticks and ratings, the phrase of the day, the fun fact of the day, game scores, a diary reflection, adding to the shopping list and marking something bought, acknowledging a family update, Lauren marking her note read, adding a phrase or a dish, saving a written note or link, and putting an idea on the planning board or voting on one. What is left out is deliberate: anything that **reshapes the plan** needs the latest revision to be safe, a stale exchange rate or forecast **overwriting a fresher one** is worse than not saving it, and a janken hand thrown into a queue is not a game.

**One bad update cannot jam the queue.** If the family plan has moved past a queued change — the activity it belongs to was deleted while a phone was out of signal — that one is dropped with an explanation and everything behind it still syncs, instead of sitting at the head of the queue blocking the rest forever.

**Voice notes wait on the phone.** A recording is megabytes of audio, so it cannot go in the little JSON queue; it goes into the phone's own IndexedDB store instead, survives the app being closed, and is uploaded on its own once there is signal. The panel shows what is waiting and lets you delete one unsent. If the signal drops mid-upload the recording is kept rather than lost. Where a phone refuses storage altogether — a private window, storage switched off — the app says so plainly instead of pretending to have saved it.


The build script precaches the app shell and versioned CSS/JS. A signed-in itinerary is saved on the device after successful loading. Guide pages and tickets are downloaded only when the user chooses Save. Downloads are network-first while connected; an authentication failure does not fall back to private cached content. With no connection, explicitly cached pages/tickets remain accessible.

Offline progress stores an operation ID, original revision and timestamp. When reconnecting, a changed server revision prompts review. Repeating a successfully submitted operation does not apply it twice. Other edits require connectivity and are never silently merged. Mobile browsers can evict site data: before travel, check that the app and selected tickets reopen in airplane mode. Keep critical tickets available through their official provider too.

- **Games for the boys:** nineteen, under More → The plan → **Games**. Seventeen work with no signal at all; each one says for itself what it needs.
  - **Which of them are Japanese games, and which are games about Japan.** A game that really is one carries a mark on its button and a line saying what it is and how long it has been played — **Traditional** for karuta, fukuwarai, daruma, shiritori, goldfish scooping, sumo, origami and janken, and **Japanese** for animal shogi, which is a new game and an old one at the same time, and for picross, which is the one puzzle in here that really was invented in Japan. The rest carry nothing, because they are ours: Onigiri to Fuji is a merge game with Japanese things in it, which is a different claim and is not made. The distinction is in here because it is so often fudged, and sudoku is the case that proves it — an American puzzle out of Indianapolis in 1979 that Japan named and made famous, and that has been called Japanese ever since. A boy told a game is Japanese should be told something true.
  - **Match the letters** — a memory game of **four to ten pairs** over hiragana or katakana, tap the letter then the sound it makes. Where the phone has a Japanese voice it reads each letter aloud at half speed as it is turned over, so Nate is matching a shape to a sound rather than to a squiggle. Best score kept per person per alphabet, fewer taps being better.
  - **Read the sign** — the katakana decoder, and the one that pays off on a real menu. Every foreign word in Japanese is written in katakana, so a child who can sound out コーヒー can read half a café menu. Forty real words off menus, signs, vending machines and lift panels, each with a line on where it turns up. A run counts up while the answers are right and resets when one is wrong.
  - **Karuta** (かるた) — the New Year game, and the one that pays back what Match the letters teaches. The cards lie face up, the reader calls one, and the first hand on it keeps it — which on one phone means the clock is the brother you are racing. **Three decks**: hiragana and katakana, where the reader calls a sound and you take the letter that makes it, and **ことわざ**, twenty-three proverbs a child can picture. The proverb deck is the real thing, *iroha karuta*, where the card is found by the letter the reading opens with — so 転ばぬ先の杖 is under こ, and the picture is only there to be recognised across a table. **The call is never written on the card**, because a card that shows you the answer is a matching game, and there is already a matching game two buttons to the left. The phone reads each call aloud in Japanese where it has a voice for it: a letter slowly, a whole proverb at ordinary speed, because a saying read at half speed is a dirge. A hand on the wrong card is an **otetsuki** — in a real game it costs you a card you had already won; here it costs points and the card flinches, because a five-year-old who has cards taken back off him stops playing. A round is worth what is left of a perfect one, so it is always worth hurrying. **The same seed deals the same floor and the same reading order**, so the two of them can race it properly rather than arguing about who got the easier one. Best score kept per deck and per number of cards.
  - **Animal shogi** (どうぶつしょうぎ) — three squares across, four down, four animals, and it is real shogi. **Take a piece and it changes sides**, and you put it back on the board as one of yours, which is the part that makes shogi shogi rather than chess. A 🦁 lion moves one square any way, a 🦒 giraffe straight, a 🐘 elephant on the diagonal and a 🐤 chick one square forward — and a chick that reaches the far row is a 🐔 hen and has no say in it. **Two ways to win**: take his lion, or walk yours all the way to his back row and survive there, which is the *try*, and it is not a win if something can take you the moment you arrive. **Three opponents** — Chick takes what is in front of him, Giraffe looks a move or two ahead and will set a trap, and Lion sees the whole thing coming. Your side is the bottom of the board always, because a board that turns around between moves is how a child loses track of which lion is his. Nothing about this one leaves the phone: he decides in a few milliseconds, and the pause before he moves is there so a piece does not vanish from under the finger that just moved. A win pays by how hard he was and how short the game was, and the points add up across a sitting.
  - **Janken** — rock, paper and scissors as Japan actually plays it (グー・チョキ・パー, called with *saisho wa guu, jan-ken-pon*), across two phones. **Neither hand is sent to the other phone until both are thrown**: the redaction happens at the response boundary in `server/visibility.mjs`, not in the screen, because a hidden screen is one fetch away from being read. A thrown hand cannot be changed, a draw scores nobody, and the running tally is shared. It needs both phones online and polls a little faster while a hand is waiting to be answered.
  - **Fukuwarai** (福笑い) — the New Year one, played blindfolded, and the only game in here where losing is funnier than winning. **You get a look at the face, and then it goes.** The blindfold takes the whole thing with it: what is left is the edge of the board, the way it is at a table with a scarf round your eyes, and you place from memory. **Six pieces, handed over one at a time in a fixed order, and there is no going back** — eyebrows, eyes, nose, mouth. **Nothing appears as you place it.** A tap leaves a faint numbered mark, which is the hand you can still feel where you last put it: it says a tap landed and roughly where, which is what you get at a table, and nothing more. **Two faces**, which are the two it is always played with: お多福, the round pleased one whose name means much good fortune, and ひょっとこ, the comic one blowing on a fire through a bamboo pipe — **and his mouth belongs off to one side**, so putting it in the middle is the mistake the face is designed to catch. Then the blindfold comes off and everything appears at once, with a dashed ring showing where each piece should have gone. Marked out of 150, full marks for a piece on the spot and nothing once it is a third of a face away, and the verdict at the bottom of the range is the kind one: *something has gone badly wrong, and it is much better for it*. Each face keeps its own best score. The faces are drawn by the app, so there are no picture files and it works in a tunnel.
  - **Daruma** (だるまさんがころんだ) — Japan’s red light, green light. He faces the wall and chants, you creep up behind him, and on the last syllable he spins round — anybody still moving is caught. **Hold the button to move, let go before he turns.** The chant is the game: ten syllables lighting up one at a time, **each with its own length**, leaning slow at the start and rushing the end exactly as a child does it, so you are watching the syllables rather than counting seconds. He is the 鬼, the demon, which is what the child at the wall is called in every Japanese chasing game. **Three of him** — やさしい, ふつう and おに — and what actually changes is how long you have to stop once he starts turning: about a second, two-thirds of a second, and a third of a second. Those were picked by playing each level against a reaction time rather than guessed, which is why the gentle one is winnable by a five-year-old every time and the demon is not meant to be. **Three lives**; caught sends you back to the wall, and the third time is the end of it. A finger left on the glass is still a finger on the glass, so being sent back does not stop you creeping the moment the chant restarts. Touching him pays by which demon it was, how quick you were, and the lives you did not need. It says the phrase aloud where the phone has a Japanese voice, because it is the one line of Japanese the boys are most likely to hear shouted in a playground.
  - **Shiritori** (しりとり) — the word chain every Japanese family plays on a train, and the chain opens on the word しりとり itself, which is how it is really started. Your word has to begin with the **last sound** of the one before it, no word twice, and **a word ending in ん loses**, because nothing in Japanese begins with ん. That one rule is why it is worth playing while you are learning kana: it makes a child read the end of a word, which is the half nobody ever looks at. **It works on sound rather than spelling**, which is where all the fiddly bits live — カレー ends on れ, because ー is a held vowel and not a letter; じんじゃ ends on や, because a small kana counts as its big one; and か and が are the same letter, which is how children play it and is said so on the screen. **Two ways in.** *Pictures* is four cards, every one with a picture, and **nothing Nate can legally pick can lose the game for him** — when the only word that fits is a trap the chain runs dry instead, because handing a five-year-old a position whose only legal card loses is not a harder puzzle. *Words* is eight cards, no pictures, and one of the right answers ends in ん. **The phone plays to win** and never walks into the trap itself; when it runs out of words it says so, and that is how you beat it. The word list was **measured rather than guessed**: the first draft averaged four words a game because seven words led into り and exactly one led back out, so thirty more were added for the letters the chain was strangling on, and a game now runs about thirty words. A test holds the list to having no dead ends at all.
  - **Goldfish scooping** (金魚すくい) — the festival stall, and they will stand in front of a real one. A paper scoop and a bowl: **hold a finger on the tank** and the scoop goes under, slide it beneath a fish, **lift the finger** and you have it. **The paper always goes in the end**, which is not a bug and is the entire business model — the man running the stall knows it and so does everybody queueing. Three things wear it out, and all three are real: **soaking**, because it is wet from the moment it goes under; **dragging it about** rather than moving it smoothly; and **greed on the lift**, where two fish at once costs far more than twice one fish. The fish **scatter from the scoop**, which is most of why it is hard. **The difficulty is the paper grade** — 四号, 五号, 六号, and the higher the number the thinner it is, which is how a real stall sets the odds; thicker paper catches more fish and thinner paper pays more for each. Three kinds of fish, and **the slow ones are worth more**, which is also true of the stall: the black でめきん is a poor swimmer and everybody goes for it. They are **drawn rather than emoji**, because there is no black fish in the emoji table — the nearest one comes out blue, and a black moor that is blue is a thing a child notices — and drawing them means they look the same on every phone. A test plays the game headlessly and holds the technique to paying: a careful hand beats a greedy one and a hurried one on every grade of paper.
  - **Picross** (お絵かきロジック) — nonograms, and **the genuinely Japanese puzzle in here**, which is the whole reason the games list carries an origin mark at all. Two people invented it independently in Japan in 1987 — Non Ishida, who won a competition with it, and Tetsuya Nishio — and it went out from there. Sudoku is the opposite story and gets no mark: American, out of Indianapolis in 1979, named and made famous in Japan, and called Japanese ever since. The numbers down the side and along the top say how many squares in that line are filled and in what order, **3 1** meaning three together, a gap, then one. **Nothing in here needs guessing.** There is a solver in the code that only ever deduces and never guesses, and it exists to keep puzzles out rather than to play them: a picture it cannot finish is one a person would have to guess at, so it never ships. A test runs it over every picture on every build, and two pictures were drawn, failed it, and were redrawn or thrown away. **Nineteen pictures**, eight at five squares and eleven at ten, all of them Japanese — a torii, a paper crane, a daruma, a lucky cat, Fuji twice at two sizes. **The name is kept back until it is solved**, because a puzzle that tells you what you are drawing has given away half of what you were working out; solved ones show their name in the list afterwards and unsolved ones are just numbers. Filling a square that should be empty is **not stopped and not undone** — you work it out and cross it back off — but it is counted, so that guessing does not out-score working it out.
  - **Onigiri to Fuji** — the merge game, on a four by four board. Two of the same become the next one up, climbing a Japanese ladder: rice ball, dango, ramen, sushi, maple leaf, cherry blossom, torii gate, Nara deer, castle, Shinkansen, Mount Fuji. Swipe or use the arrows. A pair merges once per move, not in a chain, and the game ends when there is no space and no pair left anywhere.
  - **What we did** — a memory game built out of the trip itself: match the thing we did to the day we did it. It only appears once a few activities have been ticked off, and it grows as the trip does, so by the last week it is a quiz about your own fortnight.
  - **Japan pairs** — picture memory, **four to eighteen pairs**, over eighteen things you will actually see: a torii gate, a Shinkansen, a lucky cat, a hot spring. Each card gives the English and the Japanese, so it teaches the names while it is being played. Emoji rather than image files, so it adds nothing to download and works with no signal.
  - **Make it** — two things make a third: **drag one onto another**, or tap them in turn. Start with rice, water, fire, fish, soy beans, wheat, tea leaves and seaweed, and work out the other sixteen: rice and water make cooked rice, cooked rice and seaweed make an onigiri, noodles and miso soup make ramen. Every one is something a child could be told and would believe, everything is reachable from the eight you start with, and no recipe makes one of its own ingredients.
  - **Sushi snake** — snake, eating sushi, **quicker with every piece** — from 260ms a step down to a floor of 110ms, which is still steerable. It starts at the near wall rather than the middle, which is about ten cells of room before the far wall instead of the second and a bit a mid-board start gives you.
  - **Sumo stable** — the merge-and-battle one. Sixteen squares; **drag one wrestler onto another** of the same rank, or tap them one after the other and one of them is promoted, up the **real sumo ladder** — jonokuchi, jonidan, sandanme, makushita, jūryō, maegashira, komusubi, sekiwake, ōzeki, yokozuna — so it teaches the ranks on the way up. Build one big enough and send him out against a challenger near your own rank. A bout is decided mostly by rank but never entirely: a yokozuna is not certain and a beginner is not hopeless, because an upset is the only reason to watch. Winning pays by the rank you beat; losing costs your best wrestler a rank. Two of the same rank only, nothing goes above a yokozuna, and a full stable takes no more recruits.
  - **Sumo** — the whole bout, ceremony and all, because at the sumo the lead-up is most of what you actually watch and the bout itself is over in seconds. **Three rituals first**, each a small game of its own and each buying something in the ring rather than points on the board: **the stamps** (*shiko*, 四股) on the beat, four of them, left and right, and a deep stance is a long wind; **the salt** (*shio-maki*, 塩まき), a sweep to stop on the band, and a good throw brings the crowd with you so an opening stays open longer; and **the charge** (*tachi-ai*, 立合い) — crouch, hold, and go the moment the gyoji calls *hakkeyoi*, which is ground you already own when the two of them meet. Go early and it is a **matta**, a false start, and he starts with the ground instead.
    Then the bout, which is no longer a tapping race. Every shove costs what it earns, so a whole bar of mashing crosses a fraction of the ring and leaves you with nothing in your legs; **brace** when he gathers himself for a surge (into it and he walks you back, bracing with nothing coming and he walks you back anyway); and when he leaves something open, **read the tell and name the move** — chest wide open is *oshidashi*, a grip on his belt is *yorikiri*, charging in head down is *hatakikomi*, an arm high and loose is *uwatenage*. The right one for that tell wins two paces, the wrong one overbalances you, and mashing straight past an opening loses it. The two slowest speeds name the move alongside the tell, because Nate is five; the rest expect you to know it. **Seven speeds**, from Beginner through Nate-, Boston-, Mum- and Dad-speed to Ozeki and Yokozuna, each faster than the last and each worth more than the last — a harder bout has to pay better or nobody would pick it — and **a clean ceremony pays on top of the win**, up to half as much again, which is the point: the salt is not decoration.
    **Five ways into the ring**, off the stable's own front door. **Quick bout** (*butsukari-geiko*, ぶつかり稽古) is two taps from the games list to pushing: no ceremony, no waiting, the stance and the salt taken as read — a fair stance, a fair throw, a fair charge — so it is the ring on its own and neither a punishment for skipping the salt nor a shortcut worth taking anywhere that counts. It is practice, so nothing it does is written down. **Training** (*keiko*, 稽古) is the morning practice: each ritual on its own — the stamps, the salt, the charge, which tells you how many milliseconds you took — plus a **read the tell** drill that asks which of the four moves answers which opening with nothing on the clock, the quick bout again, and a full practice bout at any speed. **Nothing in training is written down**, which is the whole point of practice. **One bout** (*ichiban*, 一番) is the old game: one bout at a family speed, worth points, best score kept as it always was.
    **The climb** (*banzuke*, 番付) is the way up. Beat the man on the rung above and you take his rank, up the four unpaid divisions — jonokuchi, jonidan, sandanme, makushita; lose and you go back down one, and nobody falls out of the bottom. Reach **jūryō**, where a wrestler starts being paid, and you are a **sekitori**: on the banzuke, and the tournament opens.
    **The tournament** (*basho*, 本場所) is seven days, one bout a day — which is what a lower-division tournament really is. The schedule is built like a real torikumi: below you to start with, above you at the end, the worst of them saved for **senshūraku**, the final day. **Four wins is kachi-koshi**, a winning record and a promotion; three or fewer is **make-koshi** and your name moves down the sheet, though a sekitori stays a sekitori. Seven from seven is a **zenshō-yūshō**, a perfect tournament, and it is counted. The six tournaments of the year come round in order — Hatsu, Haru, Natsu, Nagoya, Aki, Kyūshū — starting with the **Aki basho in Ryogoku**, the one that is on in Tokyo while we are there.
    Your current rank lives on the phone, so a closed tab does not cost you a career; the **highest rank you have ever reached** and your best tournament sync like any other score, because that is the part a brother wants to see.
  - **Draw it** — step by step drawing, the way the art channels do it: one line at a time, and **the line arrives along itself** rather than appearing finished, which is the difference between being shown how and being handed a picture to copy. A step is a sentence and a picture — *two horns sweeping back off the top, one each side, like a pair of thick leaves* — everything drawn so far stays on the page underneath, and the construction circles are drawn as faint dashes and called guides, because they are rubbed out at the end.
    **Two ways to do it.** **On paper**, which is the point of it — the phone holds the step, you draw on a serviette on a train, and when it is finished you **photograph what you drew**. Or **side by side**, with the steps above and a pad on the phone below: a full palette of twelve pens, four nib widths, an eraser, undo one line at a time, and start again. The pad has three modes of its own — **freehand**, **ghost trace** (the finished line work sitting faint under your pad to draw over), and **colour in** (the drawing printed on the pad in ink, with your colour going underneath it so the lines stay on top of the paint, the same as a colouring book).
    **Fifteen things to draw, and as many more as they invent.** Five **spinner tops**, five **beast crests** — dragon, tiger, phoenix, rhinoceros beetle, fox — and five **manga faces**: the chibi head, the manga eye on its own, a shiba inu, a rikishi and a mecha helmet. The tops are **built rather than drawn**: a top is a ring style, a number of blades, a beast and a name, and its steps are worked out from those, so **build your own** — pick the ring, drag the blades from three to eight, choose the beast, name it — and it gets proper step-by-step instructions of its own, the same as ours. Your tops are kept on the phone. Every beast is drawn once and used twice: full size as a crest, and shrunk into the forge disc of a top, so the decal can never disagree with the crest. None of it is anybody else's artwork — the shop tops and their characters belong to the people who drew them, and these are ours, built out of circles and lines so that a child can copy them and own the result.
    **The lines themselves.** A shape can be filled in and a line can be heavy or light, which is most of the difference between a drawing and a wiring diagram: the eyes of a chibi are filled black with two white spots left in them, a tiger's stripes and a fox's ears are solid, a mecha's visor is black with the eyes cut out of it, and the outline of a head is drawn heavier than the whiskers on it. A filled shape is still **inked along its outline first and floods afterwards**, so it is drawn rather than stamped. The beasts are the ones you would recognise — the dragon is side on, with the snout, the swept horn and the open jaw, because a dragon head drawn from the front reads as a lizard; the phoenix has its wings thrown up with feathers cut into them; the tiger is all cheeks. The spinner tops are **blades rather than spokes**: each blade is a chunk, wide where it meets the hub and leaning the way the top turns, with as much gap after it as blade — which is what a top looks like from above, and what the first version of this did not.
    **Kept on the phone first, sent to the family second.** A finished drawing is saved into the phone's own storage whether there is signal or not — the pad flattened onto white paper, with the printed lines back over the top if it was a colouring-in — and when there is signal it goes into the family's gallery of drawings as well, where anybody can look at everybody's. It stays on the phone either way, so it still opens on a train with nothing. **A drawing is not entered in the photo of the day**: nobody wants a drawing competing with a picture of a bullet train for the family's votes, so they are kept apart, with sixty each and a boy able to remove only his own. Drawing anything at all marks it as drawn, and the brothers can see whose name is against which one.
  - **Spot the difference** — made out of **our own photographs**. One of the two pictures is quietly changed in three, five or seven places, and you tap wherever you see it, in either picture. Everything happens on the phone: the photo is measured, the changes are chosen and painted, and **nothing about a round is sent anywhere** — the only thing that needs signal is the photo coming down once.
    - **The picture is measured before it is touched.** A change hidden in a blank sky cannot be found, so only places with enough going on are edited, they are kept well apart rather than clustered in one corner, and a patch of colourless grey is never chosen for a recolour. If a photo is too plain to hide the changes fairly, it **says so and refuses to make a round** rather than producing one nobody could win.
    - Five kinds of change: something is covered over by what is beside it, something from elsewhere in the picture appears twice, a patch is mirrored, grown, or has its colours rotated. Each is **faded out at its edges**, so the game is looking at the photo rather than hunting for a seam.
    - **The same photo at the same level is the same puzzle on every phone**, so the two of them can race it properly, and everybody's best on that photo is listed under the board.
    - Tapping one you have **already found costs nothing** — being sure of an answer you already gave should not cost a five-year-old points. A find is always worth more than a wrong tap costs, so looking is never punished into not looking. A hint circles the area rather than the thing and costs points; **a round you reveal is not scored at all**.
    - The two pictures go **side by side or one above the other**, whichever gives each of them more room — which on a phone held upright means stacked, and side by side the moment it is turned, without being asked, and does the right thing for a tall photo either way.
  A best score is kept **per board size**, so a four-pair round cannot flatter an eighteen-pair one. Scores go up and never down, each person keeps their own, and the boys can only score for themselves. **A score earned with no signal is kept and synced later**, like a completed mission — the phone shows it straight away rather than looking like it did nothing. A janken hand is deliberately not queued: a hand thrown into a queue is not a game.

## Daily thank-you notes (Damien → Lauren)

A private note from Damien appears as a pop-up for Lauren once on each day of the trip.

**What each person sees**

| | Pop-up | The note list | Schedule and read receipts |
| --- | --- | --- | --- |
| Damien | No | Yes — writes, amends, reorders, pins, removes | Yes |
| Lauren | Yes, once per trip day | No | No |
| Nate, Boston | No | No | No |

**How the schedule works.** The notes are a single ordered list, seeded with 20 written suggestions. Each trip day takes the next note in list order, so reordering the list changes which day gets which note. A note can instead be pinned to a specific day; pinned notes always land on their day and the unpinned ones fill the days around them. A day accepts only one pinned note. With 20 notes and 16 trip days, the surplus sits at the bottom of the list as spares until Damien moves one up. Damien can amend any wording, add his own notes, or delete ones he does not want.

**Read receipts.** Damien's page shows whether Lauren has opened each day's pop-up. A tally above the schedule counts the notes opened out of those already delivered and names any she has not opened. Each schedule row and each note card then carries its own state: a green tick and the Japan time she opened it, or `Not opened yet` for today, `Not opened` for a day that has passed, and `Waiting` for a day still to come. A note opened after midnight in Japan shows the date she actually read it (`Read Wed, 23 Sept · 07:05 JST`), so a late read is not mistaken for one on the day. Only days that have arrived and carry a note count towards the tally. Lauren sees her own receipt on the note itself; the tally and the schedule are Damien's alone.

**How Lauren sees it.** The note opens automatically the first time she opens the app on that day, in Japan time. Closing it records that she opened it and it does not reopen. A heart in the top bar reopens the day's note whenever she wants it, with a dot until she has read it. Dismissal is also recorded on the phone itself, so the note does not reappear if she is offline when she closes it.

**Privacy.** This is enforced on the server, not only in the interface. `server/visibility.mjs` redacts the trip state at the response boundary: Damien receives the full list, Lauren receives only the text scheduled for the current Japan day, and Nate and Boston receive neither. The note text is never sent to a phone that is not meant to read it, so it is not in the cached offline snapshot or the itinerary backup download for those family members. The notes are also kept out of Family updates and the "Recent family changes" history, so no one sees that a note was written or read. Damien is the only person who can write or change a note; Lauren is the only person who can mark one read. Both rules are checked server-side by family-member name, not only by parent role.

**Limitations.** The pop-up appears when the app is opened or refreshed — it is not a phone push notification, and nothing is sent if Lauren does not open the app that day. Marking a note read needs connectivity; offline, the phone remembers the dismissal and the read receipt is simply not recorded. Anyone holding Damien's parent invite link can read and edit the list, so treat that link as private.

### Turning the guide
